# 360 PhotoCap

By NorthXbar

แอพ Android ถ่ายภาพ 360° แบบ photo sphere: แอพวางจุดเป้าบนทรงกลมรอบตัวผู้ใช้ ผู้ใช้หมุนกล้องเล็งตามจุด แอพถ่ายอัตโนมัติเมื่อเล็งตรงและถือนิ่ง แล้วต่อภาพเป็น panorama แบบ equirectangular (2:1) พร้อม metadata GPano ให้ Google Photos / Facebook เปิดเป็นภาพ 360 ได้

## ดาวน์โหลด APK

ทุกครั้งที่ push เข้า `main` GitHub Actions จะ build APK ให้
แท็บ **Actions** → run ล่าสุด → **Artifacts** → `360PhotoCap-apk`

Build เอง: `./gradlew assembleRelease` (ต้องมี JDK 17 + Android SDK)

## การทำงาน

1. **อ่านทิศกล้องด้วย gyroscope** (`OrientationTracker.kt`)
   - ใช้ `TYPE_GAME_ROTATION_VECTOR` ซึ่ง Android รวม gyroscope + accelerometer ให้ โดย**ไม่ใช้เข็มทิศ** จึงไม่เพี้ยนเพราะโต๊ะเหล็ก/ตู้เหล็กในอาคาร
   - ถ้าเครื่องไม่มี sensor นี้ จะอินทิเกรต `TYPE_GYROSCOPE` เองด้วย quaternion และใช้ accelerometer แก้ drift ของ pitch/roll (Mahony filter)
   - ผลลัพธ์คือเมทริกซ์การหมุน **R** (device → world)
2. **วางเป้า** (`SphereMath.buildTargets`) ตาม FOV ของกล้องที่อ่านจาก Camera2
3. **วาดเป้าทับภาพกล้อง** (`TargetOverlayView.kt`) และแสดงภาพที่ถ่ายแล้วเป็นกรอบสีเขียว
4. **ล็อกแสง** ก่อนภาพแรก: อ่านค่าที่กล้องวัดอัตโนมัติไว้ (ISO, ชัตเตอร์, white balance, โฟกัส) แล้วตั้งเป็นค่า manual ตลอดการถ่าย
   (AE_LOCK/AWB_LOCK เป็นแค่คำขอที่บางเครื่องไม่ทำตาม) ถ้ากล้องไม่รองรับ manual จะถอยไปใช้ AE/AWB lock
   ตอนต่อภาพจะอ่าน EXIF ถ้าค่าแสงยังต่างกัน จะชดเชยด้วย k^(1/2.2) (JPEG ≈ gamma 2.2)
5. **ถ่ายอัตโนมัติ** (`CaptureActivity.kt`) เมื่อเล็งห่างเป้า < 3°, เอียงข้าง < 12°, หมุนช้ากว่า 0.1 rad/s ต่อเนื่อง 450 ms
   ถ้าขยับเกิน 1.5° ระหว่างชัตเตอร์ทำงาน จะทิ้งภาพแล้วให้ถ่ายใหม่ และล็อก AE/AWB ตั้งแต่ภาพแรกให้สีทุกภาพเท่ากัน
6. **จัดภาพให้ตรงกัน** (`Aligner.kt`) หาจุดที่ตรงกันระหว่างภาพที่ซ้อนกัน แล้วปรับทิศของแต่ละภาพและค่า FOV ให้รอยต่อสนิท (รายละเอียดด้านล่าง)
7. **ปรับความสว่าง + หารอยต่อ + ผสมหลายความถี่** (`StitchCore.prepare`) ทำให้ทุกภาพสว่างเท่ากัน แล้ววางรอยต่อให้เลี่ยงวัตถุใกล้ที่เหลื่อมกัน
8. **ต่อภาพ** (`StitchCore.kt`) แบบ inverse mapping ใช้ทุก core ของ CPU
9. **บันทึก** (`PanoSaver.kt`) ลง `Pictures/360PhotoCap` พร้อม XMP GPano และเปิดดูในแอพด้วย OpenGL (`PanoViewerView.kt`)

## การคำนวณ

**แกนพิกัด** (แบบเดียวกับ Android SensorManager)
- World: X = ตะวันออก, Y = เหนือ (กับ game rotation vector คือทิศอ้างอิงที่เครื่องเลือกเอง), Z = ขึ้นบน
- Device (แนวตั้ง): X = ขวา, Y = หัวเครื่อง, Z = พุ่งออกจากจอ กล้องหลังมองไปทาง −Z
- `w = R · d` แปลงจาก device เป็น world

**FOV กล้อง**

```
tan(FOV/2) = (ขนาด sensor × activeArray/pixelArray) / 2 / ระยะโฟกัส
```
แล้วครอปตามอัตราส่วนภาพจริง (4:3) ด้วย `cropTan`

**ทิศของเป้า** (yaw θ จากทิศแรกที่ถ่าย, pitch φ)

```
v = (cos φ · sin(θ+θ₀), cos φ · cos(θ+θ₀), sin φ)
```

**จำนวนเป้า** (overlap 35%)

```
ระยะห่างแถว  = vFOV · (1 − overlap)
ภาพต่อแถว    N = ceil(360° · cos φ / (hFOV · (1 − overlap)))
```
กล้องทั่วไป (แนวตั้ง ~50° × 65°): แถวกลาง 12 + แถว ±41° แถวละ 9 + เพดาน 1 + พื้น 1 = **32 ภาพ**

**เช็กว่าเล็งตรง**

```
f = R · (0, 0, −1)        มุมคลาด = arccos(f · v)
```

**ฉายเป้าลงจอ**

```
p = Rᵀ · v,  depth = −p.z
x = cx + (p.x/depth)/tan(hFOV/2) · W/2
y = cy − (p.y/depth)/tan(vFOV/2) · H/2
```
ขอบภาพเป็นเส้นวงกลมใหญ่บนทรงกลม จึงฉายลงจอเป็นเส้นตรง วาดกรอบภาพที่ถ่ายแล้วได้จาก 4 มุมพอ

**จัดภาพให้ตรงกัน (แก้ภาพซ้อน)** `Aligner.kt`

1. หามุม (Shi-Tomasi corner) แบบกระจายเป็นตาราง 12×16 ช่องในแต่ละภาพ
2. ทุกคู่ภาพที่ซ้อนกัน: ใช้ R จาก gyroscope ทายว่ามุมจากภาพ i จะไปอยู่ตรงไหนในภาพ j
   แล้วบิดแพตช์รอบจุดนั้นให้เป็นมุมมองของภาพ j ด้วย homography `H = K_i · R_iᵀ · R_j · K_j⁻¹`
   จากนั้นค้นหาด้วย normalized cross-correlation จากหยาบไปละเอียด 3 ชั้น
   (ชั้น ¼ ค้น ±16 px ≈ ±7°, แล้ว ±2 px) และหาตำแหน่งละเอียดกว่าพิกเซลด้วย parabola
   ตัดจุดที่กำกวม (ลายซ้ำ เช่น กระเบื้อง) ด้วยการเทียบยอดที่ 1 กับยอดที่ 2
3. Bundle adjustment (Levenberg-Marquardt) ปรับการหมุนเล็กๆ ωᵢ ของทุกภาพ + สเกล FOV ร่วม σ:
   ```
   r = normalize(Rᵢ·vᵢ) − normalize(Rⱼ·vⱼ),     v = (nx·tanH·eᵠ, ny·tanV·eᵠ, −1)
   Rᵢ ← exp([ωᵢ]×)·Rᵢ,   ∂r/∂ωᵢ = −[uᵢ]×,   ∂r/∂ωⱼ = +[uⱼ]×
   ต้นทุน = Σ Huber(|r|, 0.23°) + w·Σ|log(Rᵢ·Rᵢ,gyroᵀ)|² + w·σ²
   ```
   prior เบาๆ ดึงไว้ใกล้ค่า gyroscope เพื่อให้เส้นขอบฟ้าตรงและล็อกการหมุนรวม
   ตัด outlier (> max(0.57°, 4×median)) แล้วปรับซ้ำ
4. ถ้าจับคู่ได้น้อยหรือผลแปลก (rms > 1°, FOV เปลี่ยน > 15%, ภาพไหนขยับ > 12°) จะกลับไปใช้ค่า gyroscope

ผลทดสอบกับฉากจำลอง (32 ภาพ, gyro คลาดสุ่ม ≤ 2.5°, FOV ผิด 3%):
ความคลาดการหมุนระหว่างภาพ 4.5° → **0.03°**, FOV กลับมาถูก, ความต่างสีตรงรอยต่อ 21 → **1.8** (จาก 255)

**ปรับความสว่างระหว่างภาพ (gain compensation)**

Īᵢⱼ = สีเฉลี่ยของภาพ i ในส่วนที่ซ้อนกับภาพ j, Nᵢⱼ = จำนวนพิกเซลที่ซ้อน หา gain gᵢ (แยก R,G,B) ที่ทำให้
```
Σ Nᵢⱼ [ (gᵢĪᵢⱼ − gⱼĪⱼᵢ)²/σn² + (1−gᵢ)²/σg² + (1−gⱼ)²/σg² ]   ต่ำสุด     (σn = 4, σg = 0.2)
```
เป็นสมการเชิงเส้น A·g = b แก้ตรงๆ ได้ จำกัด g ไว้ที่ 0.8–1.25
ผลทดสอบ: สุ่มความสว่างแต่ละภาพ ±15% (ต่างกันสูงสุด 34%) → หลังปรับต่างกันเหลือ 1.3%

**หารอยต่อ (seam finding)** แก้ parallax ที่การจัดภาพแก้ไม่ได้

ทำบนตารางละติจูด/ลองจิจูดความละเอียดต่ำ (กว้าง ≤ 1024) ให้ทุกพิกเซลเลือกภาพเจ้าของ 1 ภาพ โดยลดพลังงาน
```
E = Σ_พิกเซล  60·(margin ดีสุด − margin ของภาพที่เลือก) + 2000·max(0, 0.06 − margin)²/0.06
  + Σ_พิกเซลติดกันที่เลือกต่างภาพ (a,b)  |Iₐ − I_b|(p) + |Iₐ − I_b|(q)
```
- เทอมแรกแทบไม่มีผล ยกเว้นใกล้ขอบภาพ (< 3.5°) → รอยต่อย้ายไปไหนก็ได้ในโซนซ้อน
- เทอมที่สองแพงตรงที่สองภาพเห็นไม่ตรงกัน (วัตถุใกล้ที่เหลื่อม) และถูกตรงที่เห็นเหมือนกัน (ผนัง พื้นเรียบ)
  → รอยต่อจึงวิ่งอ้อมวัตถุไปทางพื้นที่เรียบ

แก้ด้วย alpha-expansion graph cut (Boykov–Veksler–Zabih) ใช้ max-flow แบบ Dinic ที่เขียนเอง
ตอนเรนเดอร์ อ่านแผนที่เจ้าของแบบ bilinear จึงได้การไล่สีสั้นๆ ตรงรอยต่อ
ผลทดสอบกับฉากที่มีวัตถุห่าง 0.9 ม. และกล้องอยู่หน้าแกนหมุน 20 ซม.: ความต่างตามแนวรอยต่อลดเหลือ **44%**

**โมเดลห้อง (แก้ parallax ที่ต้นเหตุ)**

กล้องไม่ได้หมุนอยู่กับที่ แต่อยู่หน้าแกนหมุน (ลำตัว) ราว 20–30 ซม. บนทรงกลมฉากรัศมี 1 กล้องอยู่ที่ (0,0,−ρ) ในพิกัดเครื่อง
ระยะของฉากขึ้นกับทิศ: ผนังห่าง D_wall, พื้น/เพดานสูง h จากระดับกล้อง จึงได้
```
ρ(d) = max(ρ_wall, κ·|d.z|)        ρ_wall = ระยะกล้อง/ระยะผนัง,   κ = ระยะกล้อง/ความสูงพื้น-เพดาน
ฉาย:   p = Rᵀd + (0, 0, ρ(d)),   nx = p.x/(−p.z)/tanH
ย้อน:  P = (0,0,−ρ) + s·v,  |P| = 1  →  s = −c·v + √((c·v)² − ρ² + 1),  d = R·P   (วนซ้ำ 2–3 รอบเพราะ ρ ขึ้นกับ d)
```
ρ_wall และ κ เป็นตัวแปรใน bundle adjustment (prior 0.08 / 0.15) ใช้ทั้งตอนจัดภาพและตอนเรนเดอร์
ผลทดสอบห้องจำลอง (กล้องหน้าแกน 20 ซม.): rms 0.54° → 0.24°, หาได้ ρ = 0.076 (จริง 0.08), κ = 0.148 (จริง 0.148)

**ตัวยึด gyroscope ใน bundle adjustment**
- ระดับน้ำ (pitch/roll) ยึดแน่น σ ≈ 0.5° เพราะ gyro อิงแรงโน้มถ่วง ส่วนทิศ (yaw) ยึดหลวมเพราะลอยสะสม
- มุมหมุนระหว่างภาพที่ถ่ายต่อกัน ยึดตาม gyro σ ≈ 1°: `e = log(Rₖ₊₁Rₖᵀ·(R0ₖ₊₁R0ₖᵀ)ᵀ)`, ∂e/∂ωₖ₊₁ = I, ∂e/∂ωₖ = −R0ₖ₊₁R0ₖᵀ
  ภาพที่จับคู่จุดได้น้อย (เพดาน) จึงตามภาพข้างเคียง
- จุดจับคู่จากภาพก้มพื้นนับน้ำหนัก 20% (พื้นอยู่ใกล้ parallax มาก)

**บิดภาพเฉพาะจุด (mesh warp)** แก้ parallax ที่การหมุนทั้งภาพแก้ไม่ได้

แต่ละภาพมีตารางเลื่อน D ขนาด 6×8 จุด (`FrameImage.warp`) ภาพถูกอ่านที่ (nx, ny) + D(nx, ny)
สำหรับจุดคู่ a (ภาพ i) ↔ b (ภาพ j) หลังจัดการหมุนแล้ว ยังเหลือ
```
eⱼ = b − projⱼ(rayᵢ(a))        eᵢ = a − projᵢ(rayⱼ(b))
ให้แต่ละภาพขยับคนละครึ่งทาง:   Dᵢ(a) ≈ eᵢ/2,   Dⱼ(b) ≈ eⱼ/2
```
แล้ว fit ตารางของแต่ละภาพด้วย least squares + ความเรียบระหว่างจุดข้างเคียง (λs = 1.5) และดึงเข้าหา 0 เล็กน้อย
ใช้จุดคู่ทุกจุด (จุดบนของที่อยู่ใกล้คือจุดที่การหมุนอย่างเดียวคัดทิ้ง) จำกัดการเลื่อน ≤ ~3°
ผลทดสอบในห้องจำลอง (กล้องอยู่หน้าแกนหมุน 20 ซม.): ความคลาดที่จุดคู่ 1.19° → 0.74°

**จุดจับคู่หนาแน่นที่แถบรอยต่อ** (แนวคิดจาก Google Street View seam fix) หลังได้การหมุนแล้ว จับคู่จุดแบบตาราง
ทุก 16 px ในส่วนที่ภาพซ้อนกัน (ไม่ใช่แค่มุม) ด้วย NCC ค้นรอบตำแหน่งที่ทำนาย (±4/±2/±2 px บน pyramid 3 ชั้น,
NCC ≥ 0.65/0.75/0.85, ตัดจุดกำกวม/ไม่มี texture) แล้วใช้ตารางบิดละเอียด 12×16 (ค่าดึงเข้าหา 0 ปรับตามจำนวนจุด)
ไฟล์แก้ไขเก่าที่เป็นตาราง 6×8 ยังอ่านได้ (`FrameImage.gridOf`)

**เลือกผลจัดภาพจากคุณภาพรอยต่อ** (Zhang & Liu, CVPR 2014: ตัดสินการจัดภาพจากว่าหา seam ที่เนียนได้ไหม ไม่ใช่ rms)
`SeamSelect` ลองหลายสมมติฐาน: FOV กล้อง/FOV ปรับ × บิดละเอียด/บิดหยาบ และ gyroscope อย่างเดียว
ต่อแต่ละแบบบนตารางเล็ก 512×256 (gain + graph cut seam) แล้วให้คะแนน
```
score = E_seam + 240 · (ช่องที่ไม่มีภาพ)       E_seam = Σ ความต่างสีตามแนว seam
```
ใช้แบบแรกเป็นค่าเริ่มต้น เปลี่ยนเมื่อแบบอื่นดีกว่า ≥ 3% ผลทดสอบในห้องจำลองที่ gyro ดริฟต์:
บิดละเอียด 6256 · บิดหยาบ 7056 · gyroscope อย่างเดียว 91928

**วงพื้น** ไม่ถ่ายตรงลงพื้น (ติดขา) แต่ถ่าย 4 ภาพที่ −72° แทน ภาพที่มองเลยใต้เท้าไปด้านหลังจะเห็นขาคนถ่าย
จึงให้แต่ละภาพใช้เฉพาะพื้นด้านที่กล้องหันไป (`dz < −0.85` และอยู่ด้านหลัง → ข้าม) ภาพที่หันอีกทางเติมแทน

**แก้ไขแมนนวล** (`EditorActivity`, ปุ่ม "แก้ไข" ในหน้าดูภาพ)

- แตะเพื่อเลือกภาพที่ครอบจุดนั้น (แตะซ้ำเพื่อสลับภาพที่ซ้อนกัน) มีกรอบสีเขียวแสดงขอบภาพ
- **เลื่อนภาพ**: ลากเพื่อหมุนภาพรอบแกนตั้ง (yaw) และแกนนอนที่ตั้งฉากกับทิศมอง (pitch), ↺ ↻ หมุน roll ทีละ 0.5°
  `R' = Rot(แกนนอน, Δpitch) · Rz(−Δyaw) · R` ภาพที่เลื่อนจะไม่ใช้ mesh warp อัตโนมัติ
- **ระบาย**: ลากระบายตรงที่ต้องการให้ใช้ภาพที่เลือก ตอนหารอยต่อ ช่องที่ถูกระบายจะมีต้นทุนสูงมากถ้าใช้ภาพอื่น
  (`StitchCore.Paint` → `forced` ใน SeamField) รอยต่อจึงวิ่งอ้อมบริเวณนั้น
- พรีวิวแบบภาพแบน: ตอนลากใช้ความละเอียด 512 แบบไม่หารอยต่อ ปล่อยนิ้วแล้วใช้ 1024 (โหมดระบายหารอยต่อด้วย)
- บันทึกเป็น `manual.json` (หมุนแต่ละภาพ, FOV, warp, เส้นระบาย) ต่อภาพครั้งต่อไปจะใช้ไฟล์นี้แทนการจัดภาพอัตโนมัติ
  ผลอัตโนมัติเก็บใน `align.json` เป็นจุดเริ่มของการแก้ไข ปุ่ม "อัตโนมัติ" ลบ manual.json แล้วต่อใหม่

**ผสมหลายความถี่ (multi-band blending)** แก้ภาพเป็นปื้น

แยกแต่ละภาพเป็น 3 ช่วงความถี่ (คำนวณในพิกัดของภาพเอง):
```
รายละเอียด = I − L₁      กลาง = L₁ − L₂      ต่ำ = L₂        (L₁ ≈ เบลอ 1°, L₂ ≈ เบลอ 5°)
```
แต่ละช่วงผสมด้วยน้ำหนักต่างกัน: รายละเอียดใช้แผนที่เจ้าของแบบคม, ช่วงกลางเบลอแผนที่ ≈1°, ช่วงต่ำเบลอ ≈4°
ความต่างของแสงและสี (vignetting, tone mapping ของมือถือ) จึงถูกเกลี่ยเป็นแถบกว้าง ส่วนรายละเอียดยังมาจากภาพเดียวจึงไม่ซ้อน
ผลทดสอบ (แต่ละภาพมีแสงไม่สม่ำเสมอแบบสุ่ม): ความเป็นปื้นลดลง 43% ความคมเท่าเดิม

**ผลวินิจฉัย** กดปุ่ม "ข้อมูล" ในหน้าผลลัพธ์ (บันทึกเป็น diag.txt ด้วย): จำนวนภาพ, วิธีล็อกแสง, ค่าแสงจาก EXIF,
ผลจัดภาพ (จุดจับคู่, rms, ภาพที่จับคู่ได้น้อย), ช่วง gain, ต้นทุนรอยต่อ, ส่วนที่ไม่มีภาพ, เวลาแต่ละขั้น

**ต่อภาพ (equirectangular W×H)** สำหรับทุกพิกเซล (u, v):

```
lon = (u+½)/W · 2π − π         lat = π/2 − (v+½)/H · π
d   = (cos lat · sin(lon+θ₀), cos lat · cos(lon+θ₀), sin lat)
ทุกภาพ i:   p = Rᵢᵀ·d,   nx = (p.x/−p.z)/tanH,   ny = (p.y/−p.z)/tanV
           อยู่ในภาพถ้า |nx|,|ny| < 1  →  ดึงสีแบบ bilinear ที่ ((nx+1)/2·w − ½, (1−ny)/2·h − ½)
           margin = min((1−|nx|)·tanH, (1−|ny|)·tanV)     (ระยะถึงขอบภาพ ≈ เป็นมุม)
ภาพที่ margin มากสุดเป็นเจ้าของพิกเซล ภาพอื่นผสมเฉพาะแถบรอยต่อกว้าง ~2°:
           t = (marginᵢ − best)/0.035 + 1,   น้ำหนัก = smoothstep(t)
```
แบบนี้แต่ละพิกเซลมาจากภาพเดียวเป็นหลัก จึงไม่เกิดเงาซ้อน
ความกว้างภาพผลลัพธ์ = 2π · (w/2)/tanH ตามความละเอียดที่แนวนอน (จำกัดตามหน่วยความจำ สูงสุด 8192)

**Parallax** มุมเหลื่อม ≈ r · Δθ / d (r = ระยะกล้องจากแกนหมุน, d = ระยะวัตถุ)
จึงต้องถือเครื่องชิดอก หมุนอยู่กับที่ และยืนห่างวัตถุ

## ข้อจำกัดของเวอร์ชันนี้

- รอยต่อหลบวัตถุได้เฉพาะเมื่อมีทางอ้อมในโซนซ้อน วัตถุใหญ่ที่ใกล้มาก (< 1 ม.) และขวางทั้งโซนยังเห็นรอยเหลื่อม
  วิธีถ่าย: ให้มือถืออยู่จุดเดิมในอากาศแล้วเดินวนรอบมัน และยืนห่างโต๊ะ/ผนัง
- ห้องผนังเรียบมีจุดให้จับคู่น้อย การจัดภาพอาจไม่สำเร็จ (ดูผลวินิจฉัย)
- รองรับมือถือที่แนวปกติเป็นแนวตั้ง (ไม่ใช่แท็บเล็ต)
